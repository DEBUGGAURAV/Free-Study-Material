## Page 3: 3. Web Runtime Protocols: Client, Server, IP, Port & HTTP
**Classification Area:** `SYSTEM BASICS`

> ### 🛡️ CLIENT-SERVER COMMUNICATION & TRANSPORT ARCHITECTURE
> The platform communication model is built on stateless HTTP/2 and stateful WebSocket protocols. Client browsers (React 18 SPA) establish encrypted TLS 1.3 connections over TCP Port 443 to Cloudflare Anycast Edge nodes, which terminate TLS and proxy requests via keep-alive TCP connection pools to the Node.js 20 backend runtime.

### CORE PROTOCOL SPECIFICATIONS & DEFINITIONS `[PROTOCOLS]`
- Client Runtime: React 18 Single Page Application executing in student V8/WebKit browser environments across mobile and desktop.
- Backend Host: Node.js 20 containerized application executing on Render infrastructure with native libuv event-loop concurrency.
- IP Resolution: Public client IPv4/IPv6 addresses are extracted via proxy-safe headers (x-forwarded-for, x-real-ip) with loopback normalizers.
- Port Architecture: Application binds dynamically to port 5000+ with automatic collision incrementers; public traffic enters via 443 (HTTPS).
- HTTP Methods: Enforces strict REST semantics: GET for idempotent queries, POST for ingestion, and DELETE for administrative pruning.
- JSON Payloads: Lightweight, schema-validated JSON data interchange with strict 10MB body size clamping in Express middleware.

### PRODUCTION TRAFFIC ROUTING PIPELINE `[TRAFFIC FLOW]`
- DNS Resolution: Domain freestudymaterial.onrender.com routes through Cloudflare Anycast DNS with sub-5ms resolution globally.
- SSL/TLS Encryption: Automated TLS 1.3 certificate rotation with HSTS preloading preventing SSL-stripping man-in-the-middle attacks.
- Keep-Alive Connection Re-Use: Persistent TCP sockets reduce SSL handshake overhead by 80% during multi-page document reading.
- JSON Serialization: Uses native V8 JSON parser optimized with Prototype-Pollution traps in sanitize.js before object hydration.

## Page 5: 5. Life Journey of a PDF: From Ingestion to Mobile Display
**Classification Area:** `DATA PIPELINE`

> ### 🛡️ DATA LIFECYCLE: INGESTION, DEDUPLICATION & STREAMING
> Every academic document moves through an 8-stage ingestion pipeline and a 5-stage zero-disk streaming pipeline. The upload process validates binary headers, enforces smart 3-tier deduplication (SHA-256, signature, and 3.0 MB variance shield), recompresses media via dedicated worker threads, and offloads multi-part binary chunks to Telegram Singapore DC-5.

### THE 8 STAGES OF THE INGESTION PIPELINE `[UPLOAD FLOW]`
- Stage 1 (Client Pre-Flight): UploadModal.jsx computes SHA-256 hash using Web Crypto API and verifies '%PDF-' magic bytes.
- Stage 2 (Multipart Transport): File streams into server memory buffer via Multer without writing temporary files to local disk.
- Stage 3 (Security Inspection): fileSecurityInspector.js sanitizes embedded JavaScript actions and malicious /Launch exploit tags.
- Stage 4 (3-Tier Deduplication): dedupService.js evaluates SHA-256 hash, exact size, and configurable 3.0 MB variance tolerance.
- Stage 5 (Smart Compression): compressService.js strips dead PDF objects and Sharp rasterizes a 480px WebP cover thumbnail in <50ms.
- Stage 6 (Telegram MTProto Push): Slices PDF into 512KB binary parts and uploads directly to Singapore DC-5 channel via GramJS.
- Stage 7 (Dual-DB Persistence): Saves metadata in Firestore Mumbai; pushes high-speed read-cache record into Turso Edge SQLite.
- Stage 8 (Live Notification): WebSocket broker and Telegram Topic 1 broadcast 'New Document Published' to active student sessions.

### THE 5 STAGES OF THE ZERO-DISK STREAMING PIPELINE `[STREAM FLOW]`
- Stage 1: Student opens note; browser issues HTTP GET /api/notes/stream/:id with Range header (bytes=0-1048575).
- Stage 2: Server validates student JWT token and checks ipJail firewall status in memory (<0.2ms).
- Stage 3: Retrieves telegramMessageId and chunk offset from Turso SQLite cache in under 3 milliseconds.
- Stage 4: Opens TLS socket to Singapore DC-5, fetches exact 1MB slice into memory buffer, and pipes directly to HTTP response stream.
- Stage 5: Browser Virtual Canvas Reader renders high-resolution page in RAM without saving file to phone downloads folder.
